# Ansible
## 1. Introducción

### ¿Qué es Ansible?

Ansible es una herramienta de automatización sin agentes, usada para:

- Configurar sistemas.
- Despliegue de aplicaciones.
- Gestión de infraestructuras.
- Orquestación de tareas complejas.

Está basada en SSH, usa archivos YAML y destaca por ser sencilla, declarativa e idempotente (las tareas pueden repetirse sin efectos secundarios).

### Elementos básicos

| Elemento       | Descripción |
|----------------|-------------|
| Inventario     | Lista de hosts que Ansible puede gestionar. |
| Playbook       | Conjunto de tareas descritas en YAML que se aplican a uno o varios hosts. |
| Task           | Cada acción individual (ej.: instalar paquete, copiar archivo). |
| Role           | Conjunto estructurado de tareas, plantillas, handlers, variables, etc. |
| Module         | Comando específico de Ansible (ej.: `apt`, `yum`, `copy`, `user`, etc.). |
| Handler        | Acción que se ejecuta si una tarea cambia algo (ej.: reiniciar un servicio). |
| Facts          | Información recogida automáticamente de los hosts (IP, SO, memoria, etc.). |

### Ejemplo de inventario

```ini
[web]
192.168.1.10
192.168.1.11

[db]
192.168.1.12 ansible_user=root
```

### Ejemplo sencillo de playbook

```yaml
---
- name: Instalar Apache en servidores web
  hosts: web
  become: true
  tasks:
    - name: Instalar apache
      apt:
        name: apache2
        state: present
        update_cache: yes

    - name: Asegurar que apache está iniciado
      service:
        name: apache2
        state: started
        enabled: true
```

### Comandos básicos

```bash
# Verificar conexión a los hosts
ansible all -m ping

# Ejecutar una tarea ad-hoc
ansible web -m apt -a "name=htop state=present" --become

# Ejecutar un playbook
ansible-playbook site.yml

# Usar inventario personalizado
ansible-playbook -i inventario.ini site.yml
```

### Módulos comunes

| Módulo     | Uso                       |
|------------|---------------------------|
| ping       | Prueba de conexión.         |
| copy       | Copiar archivos.         |
| template   | Copiar con Jinja2.         |
| apt / yum  | Gestores de paquetes.      |
| service    | Gestionar servicios.      |
| user       | Crear/eliminar usuarios.   |
| file       | Permisos, enlaces, etc.    |

### Buenas prácticas

- Usar roles para organizar tareas complejas.
- Separar variables en `vars/` o `group_vars/`.
- Evitar duplicación usando `with_items` o `loops`.
- Mantener handlers para acciones condicionales como reinicios.

## 2. Escenario de prácticas

Para seguir este material se usará el **hipervisor VirtualBox**, donde tendremos diferentes máquinas virtuales.

Estas máquinas virtuales tendrán dos adaptadores de red:  
- **Red interna**: para conectividad entre ellas  
- **NAT**: para acceso al exterior  

Además, las máquinas contarán con **asignación de direcciones IP por DHCP**.

Podemos configurar un servidor DHCP para la red interna de VirtualBox:

```powershell
"C:\Program files\oracle\virtualbox\VBoxManage.exe" dhcpserver add --netname intnet --ip 192.168.1.1 --netmask 255.255.255.0 --lowerip 192.168.1.2 --upperip 192.168.1.254 --enable
```

En cada máquina virtual (podemos hacerlo sobre la plantilla) configuramos `/etc/network/interfaces`:

```bash
auto enp0s8
iface enp0s8 inet dhcp
```

Será necesario, para realizar conexiones SSH, establecer un **mapeo del puerto interno 22** de cada máquina al **puerto externo** elegido.

### Notas

**Nota 1:** Las direcciones IP pueden variar según el usuario.  
**Nota 2:** Se recomienda **no apagar** las máquinas, sino **guardar su estado**.  
**Nota 3:** Algunas máquinas pueden **perder la hora**, lo que puede impedir instalaciones.

Comprobación y solución:

```bash
date
sudo date -s "2025-11-03 10:30:00"
date
```

### Comprobación

Inventario:

```ini
srv1 ansible_host=192.168.10.6 ansible_user=ansible ansible_become=yes
```

Probar ping:

```bash
ansible -i hosts srv1 -m ping
```

### Playbook de prueba

```yaml
---
- name: Playbook inicial
  hosts: srv1
  tasks:
    - name: Instalar los paquetes zip y unzip
      ansible.builtin.apt:
        name:
          - zip
          - unzip
        state: present

    - name: Crear fichero /home/user/ejemplo con permisos 777
      ansible.builtin.file:
        path: /home/user/ejemplo
        state: touch
        owner: root
        group: root
        mode: "0777"

    - name: Añadir la cadena 'hola'
      ansible.builtin.shell: |
        if test "$(tail -1 /home/user/ejemplo)" != "hola"
        then
          echo "hola" >> /home/user/ejemplo
        fi
```

## 5. El comando `ansible`

Antes de ejecutar comandos ad-hoc, crear un directorio de trabajo:

```bash
mkdir -p practicas/pr01
cd practicas/pr01
touch hosts
```

Ejemplo de inventario:

```ini
[servers]
srv1 ansible_host=192.168.10.6 ansible_user=ansible ansible_become=yes
srv2 ansible_host=192.168.10.5 ansible_user=ansible ansible_become=yes
```

### Sintaxis básica

```bash
ansible -i INVENTARIO DESTINO -m MODULO -a "ARGUMENTOS" [-b]
```

### Ejemplo: ping

```bash
ansible -i hosts srv1 -m ping
```

### Copiar fichero

```bash
ansible -i hosts srv1 -m copy -a "src=/tmp/meu_ficheiro.txt dest=/tmp/copia.txt mode=0644"
```

### Instalar paquete

```bash
ansible -i hosts srv1 -m apt -a "name=apache2 state=present update_cache=yes" -b
```

## 7. Introducción a los Playbooks

Ejemplo:

```yaml
---
- name: Primer playbook
  hosts: srv1
  tasks:
    - name: Instalar zip y unzip
      ansible.builtin.apt:
        name:
          - zip
          - unzip
        state: present

    - name: Crear archivo con permisos
      ansible.builtin.file:
        path: /home/user/ejemplo
        state: touch
        owner: root
        group: root
        mode: "0777"

    - name: Añadir contenido
      ansible.builtin.copy:
        dest: /home/user/copia
        content: |
          Hola qué tal
          Espero que bien.
          Un saludo
          Martín
```
