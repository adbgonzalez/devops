# Laboratorio práctico de Docker — Parte I: **Dockerfile**

> Objetivo general: Construir imágenes reproducibles paso a paso, introduciendo progresivamente instalación de paquetes, variables de entorno, configuraciones, buenas prácticas de seguridad y optimizaciones.

- Docker instalado.
- Editor de texto.
- Sistema Linux/WSL recomendado.
- Crear una carpeta raíz `docker-lab/` y entrar en ella.

Estructura sugerida para esta parte:

## 1) Instalar un paquete simple (cowsay)
**Qué vas a hacer:** crear una imagen base sencilla, instalar un paquete del sistema y definir un comportamiento por defecto del contenedor.

**Pasos detallados:**
1) Base `debian:12-slim` (ligera y estable).  
2) `apt-get update && apt-get install cowsay` sin recomendados y limpieza de caché.  
3) `ENTRYPOINT` a `/usr/games/cowsay` y `CMD` con un texto por defecto.

**Archivos** (`01-cowsay/Dockerfile`):
```Dockerfile
FROM debian:12-slim
RUN apt-get update  && apt-get install -y --no-install-recommends cowsay  && rm -rf /var/lib/apt/lists/*
ENTRYPOINT ["/usr/games/cowsay"]
CMD ["¡Hola, Docker!"]
```

**Pruebas:**
```bash
cd 01-cowsay
docker build -t lab/cowsay:1 .
docker run --rm lab/cowsay:1 "Saludos desde un contenedor"
```

**Puntos clave:** capas, diferencia `ENTRYPOINT` vs `CMD`, limpieza de capas.  
**Criterios de éxito:** imprime el ASCII‑art de la vaca con el mensaje indicado.

## 2) Instalar Java con `apt` y descargar una app `.tar.gz` (Tomcat) con variables `ENV`
**Qué vas a hacer:** montar una imagen de ejecución Java configurando variables de entorno y descargando Tomcat en `.tar.gz` durante la construcción.

**Pasos detallados:**
1) Base `debian:12-slim`.  
2) Instalar Java con `apt`: `openjdk-17-jre-headless`, y utilidades (`curl`, `ca-certificates`, `tar`).  
3) Definir `ENV` en **dos líneas** para emplear variables encadenadas.  
4) Descargar Tomcat con `curl`, extraerlo en `/opt` y normalizar el directorio.  
5) `EXPOSE 8080` y `CMD ["catalina.sh", "run"]`.

**Archivos** (`02-java-tar/Dockerfile`):
```Dockerfile
FROM debian:12-slim

ARG TOMCAT_VERSION=10.1.29

# Se define CATALINA_HOME y se amplía PATH en dos líneas (expansión segura)
ENV CATALINA_HOME=/opt/tomcat
ENV PATH="$CATALINA_HOME/bin:/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin"

RUN apt-get update  && apt-get install -y --no-install-recommends openjdk-17-jre-headless curl ca-certificates tar  && rm -rf /var/lib/apt/lists/*  && mkdir -p /opt  && curl -fsSL -o /tmp/tomcat.tar.gz     https://archive.apache.org/dist/tomcat/tomcat-10/v${TOMCAT_VERSION}/bin/apache-tomcat-${TOMCAT_VERSION}.tar.gz  && tar -xzf /tmp/tomcat.tar.gz -C /opt  && mv /opt/apache-tomcat-${TOMCAT_VERSION} "$CATALINA_HOME"  && rm /tmp/tomcat.tar.gz

EXPOSE 8080
CMD ["catalina.sh", "run"]
```

**Pruebas:**
```bash
cd 02-java-tar
docker build -t lab/tomcat:10 .
docker run --rm -p 8080:8080 lab/tomcat:10
# Abrir http://localhost:8080
```

**Puntos clave:** `ARG` vs `ENV`, reproducibilidad de las descargas, layout en /opt.  
**Criterios de éxito:** Tomcat responde en `http://localhost:8080`.

## 3) Copiar un archivo de configuración sencillo: **Nginx**
**Qué vas a hacer:** usar Nginx y copiar un `nginx.conf` personalizado a la imagen junto con una página estática. Validar la configuración en el *build* para evitar sorpresas en runtime.

**Estructura** (`03-configs-nginx/`):
```
03-configs-nginx/
├── Dockerfile
├── nginx.conf
└── html/
    └── index.html
```

**Archivos**

`03-configs-nginx/Dockerfile`:
```Dockerfile
FROM debian:12-slim

# 1) Instalar Nginx y utilidades mínimas
RUN apt-get update  && apt-get install -y --no-install-recommends nginx ca-certificates  && rm -rf /var/lib/apt/lists/*

# 2) Copiar la configuración y el contenido estático
COPY nginx.conf /etc/nginx/nginx.conf
COPY html/ /usr/share/nginx/html/

# 3) Validar config en build (falla si hay errores)
RUN nginx -t

# 4) Exponer puerto y ejecutar Nginx en primer plano
EXPOSE 8080
CMD ["nginx","-g","daemon off;"]
```

`03-configs-nginx/nginx.conf`:
```nginx
worker_processes  1;

events {
    worker_connections  1024;
}

http {
    # Servidor principal
    server {
        listen 8080;
        server_name _;

        # Directorio con la página estática
        root /usr/share/nginx/html;
        index index.html;

        # Endpoint de comprobación
        location /health {
            return 200 'ok';
        }

        # Ruta por defecto
        location / {
            try_files $uri $uri/ =404;
        }
    }
}
```

`03-configs-nginx/html/index.html`:
```html
<!doctype html>
<html>
  <body>
    <h1>Hola desde Nginx en Docker</h1>
    <p>Este sitio está servido con una config personalizada.</p>
  </body>
</html>
```

**Pruebas:**
```bash
cd 03-configs-nginx
docker build -t lab/nginx:conf .
docker run --rm -p 8080:8080 lab/nginx:conf
# Abrir http://localhost:8080 y http://localhost:8080/health
```

**Puntos clave:** `COPY` de configs, validación con `nginx -t`, foreground con `daemon off;`.  
**Criterios de éxito:** `/` y `/health` responden correctamente.

## 4) Construcción de aplicaciones Python con `requirements.txt` (Flask)
**Qué vas a hacer:** empaquetar una API Flask simple demostrando el patrón de caché clásico (copiar `requirements.txt` antes del código).

**Estructura** (`04-python-app/`):
```
04-python-app/
├── Dockerfile
├── requirements.txt
└── app.py
```

`requirements.txt`:
```
Flask==3.0.3
```

`app.py`:
```python
from flask import Flask
app = Flask(__name__)

@app.get("/")
def hello():
    return {"msg": "hola desde docker"}

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

`Dockerfile`:
```Dockerfile
FROM python:3.12-slim
WORKDIR /app
# Caché de dependencias
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
# Copiar el código
COPY app.py .
EXPOSE 5000
CMD ["python", "app.py"]
```

**Pruebas:**
```bash
cd 04-python-app
docker build -t lab/flask:1 .
docker run --rm -p 5000:5000 lab/flask:1
# GET http://localhost:5000 → {"msg":"hola desde docker"}
```

**Puntos clave:** capas e invalidación de caché, `--no-cache-dir`.  
**Criterios de éxito:** responde JSON en `/`.

## 5) Usuario de aplicación (no ejecutar como root)
**Qué vas a hacer:** crear un usuario/grupo no privilegiado y garantizar permisos correctos sobre los archivos.

**Archivos** (`05-nonroot/Dockerfile`):
```Dockerfile
FROM python:3.12-slim
WORKDIR /app

# Crear usuario/grupo del sistema
RUN groupadd -r app && useradd -r -g app app

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt  && mkdir -p /app  && chown -R app:app /app

# Copiar como propietario app
COPY --chown=app:app app.py .

USER app
EXPOSE 5000
CMD ["python", "app.py"]
```

**Pruebas (reuse de la app del paso 4):**
```bash
cd 05-nonroot
cp ../04-python-app/requirements.txt .
cp ../04-python-app/app.py .
docker build -t lab/flask:nonroot .
docker run --rm -p 5000:5000 lab/flask:nonroot
# Dentro del contenedor: id → no root
```

**Puntos clave:** menor privilegio, impacto en volúmenes y montajes, `COPY --chown`.  
**Criterios de éxito:** la app funciona e `id` muestra UID no-root.

## 6) Construcción multietapa (multistage)
**Qué vas a hacer:** separar construcción y runtime para obtener imágenes más pequeñas y seguras.

**Archivos** (`06-multistage/Dockerfile`):
```Dockerfile
# Etapa de construcción
FROM python:3.12 as builder
WORKDIR /build
COPY requirements.txt .
RUN pip wheel --wheel-dir=/build/wheels -r requirements.txt
COPY app.py .

# Etapa final mínima
FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /build/wheels /wheels
RUN pip install --no-cache-dir /wheels/*
COPY app.py .
# usuario no-root genérico
USER 65532:65532
EXPOSE 5000
ENTRYPOINT ["python", "app.py"]
```

**Pruebas:**
```bash
cd 06-multistage
cp ../04-python-app/requirements.txt .
cp ../04-python-app/app.py .
docker build -t lab/flask:ms .
docker images | grep lab/flask
```

**Puntos clave:** reducir superficie de ataque, comparar tamaños de imagen.  
**Criterios de éxito:** imagen final más pequeña manteniendo funcionalidad.

## 7) `HEALTHCHECK`, `ENTRYPOINT` con `tini` y señales
**Qué vas a hacer:** añadir un `HEALTHCHECK` HTTP y usar `tini` para un PID 1 correcto (señales, procesos zombi).

**Estructura** (`07-health-entrypoint/`):
```
07-health-entrypoint/
├── Dockerfile
├── requirements.txt
├── app.py
└── entrypoint.sh
```

`entrypoint.sh`:
```sh
#!/bin/sh
set -e
exec "$@"
```

`Dockerfile`:
```Dockerfile
FROM python:3.12-slim
RUN apt-get update && apt-get install -y --no-install-recommends tini  && rm -rf /var/lib/apt/lists/*
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
COPY entrypoint.sh /usr/local/bin/entrypoint.sh
RUN chmod +x /usr/local/bin/entrypoint.sh

HEALTHCHECK --interval=30s --timeout=3s --retries=3   CMD python -c "import urllib.request; urllib.request.urlopen('http://localhost:5000/').read()" || exit 1

ENTRYPOINT ["/usr/bin/tini","--","/usr/local/bin/entrypoint.sh"]
CMD ["python","/app/app.py"]
```

**Pruebas:** construir y ver `STATUS` → `healthy`. Parada limpia con `Ctrl+C`.

**Puntos clave:** liveness/readiness (aquí prueba simple), propagación de señales.  
**Criterios de éxito:** `docker ps` muestra `healthy` y parada limpia.

## 8) Optimizaciones y buenas prácticas
**Qué vas a hacer:** aplicar buenas prácticas de *image hygiene*: etiquetas OCI, `.dockerignore`, ENV útiles, instalación mínima y usuario fijo.

**Estructura** (`08-optimizations/`):
```
08-optimizations/
├── Dockerfile
├── requirements.txt
├── app.py
└── .dockerignore
```

`Dockerfile`:
```Dockerfile
FROM python:3.12-slim
LABEL org.opencontainers.image.source="https://example.local/lab"       org.opencontainers.image.description="Ejemplo optimizado"       org.opencontainers.image.licenses="MIT"
WORKDIR /app

# .dockerignore evita copiar basura al build context
COPY .dockerignore /app/.dockerignore

ARG APP_VERSION=1.0.0
ENV APP_VERSION=$APP_VERSION PYTHONDONTWRITEBYTECODE=1 PYTHONUNBUFFERED=1

RUN apt-get update  && apt-get install -y --no-install-recommends curl  && rm -rf /var/lib/apt/lists/*

COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .
RUN useradd -r -u 10001 app && chown -R app:app /app
USER 10001

CMD ["python","app.py"]
```

`.dockerignore`:
```
__pycache__/
*.pyc
.git/
.vscode/
venv/
*.log
```

**Puntos clave:** metadatos OCI, impacto de `.dockerignore` en la caché, reproducibilidad.  
**Criterios de éxito:** imagen más pequeña y con metadatos visibles.

## 9) Secretos en construcción (BuildKit)
**Qué vas a hacer:** usar BuildKit `--mount=type=secret` para leer credenciales en build sin dejarlas en la imagen.

**Estructura** (`09-secrets-buildkit/`):
```
09-secrets-buildkit/
├── Dockerfile
└── .npm_token   # ejemplo de secreto (NO subir al repo)
```

`Dockerfile`:
```Dockerfile
# syntax=docker/dockerfile:1.7
FROM alpine:3.20
RUN --mount=type=secret,id=NPM_TOKEN     echo "Usando token (no persistirá en la capa)" >/dev/null
CMD ["sh","-c","echo listo"]
```

**Construcción:**
- Linux/MacOS:

```bash
cd 09-secrets-buildkit
DOCKER_BUILDKIT=1 docker build --secret id=NPM_TOKEN,src=./.npm_token -t lab/with-secret .
```
- Windows (PowerShell):
```powershell
cd 09-secrets-buildkit
$env:DOCKER_BUILDKIT=1
docker build --secret id=NPM_TOKEN,src=./.npm_token -t lab/with-secret .
```

**Puntos clave:** diferenciar build args/env/secrets; no quedan en capas ni en `docker history`.  
**Criterios de éxito:** build OK y secreto ausente del historial.

## Cheatsheet y problemas habituales
**Comandos útiles:**
```
docker build -t nombre:tag .
docker images
docker ps -a
docker run --rm -p 8080:80 imagen
docker exec -it nombre sh
docker system df
```

**Problemas comunes y soluciones rápidas:**
- Puerto en uso → cambia `HOST:CONTAINER`.
- Caché obsoleta → `--no-cache` o tocar `requirements.txt`.
- Permisos en volúmenes → cuidar `uid/gid` del usuario de la imagen.
- Dif. `ENV`/`ARG`/`secrets` → usar cada uno para su propósito.
