## A) O básico: Nginx servindo HTML local
**Que vas facer:** un servizo con porto publicado e *bind mount* de HTML estático.

**Estrutura** (`compose/01-basic/`):
```
compose/01-basic/
├── docker-compose.yml
└── html/
    └── index.html
```

`docker-compose.yml`:
```yaml
services:
  web:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html:ro
```

`html/index.html`:
```html
<!doctype html>
<html>
  <body>
    <h1>Nginx en Compose</h1>
  </body>
</html>
```

**Proba:**
```bash
cd compose/01-basic
docker compose up
# http://localhost:8080
```

**Puntos clave:** rutas relativas, `ports` vs `expose`.  
**Criterios de éxito:** páxina servida.

## B) Env vars, healthcheck e `depends_on`
**Que vas facer:** API Flask + Redis con dependencia por *health* e configuración vía `environment`.

**Estrutura** (`compose/02-env-depends/`):
```
compose/02-env-depends/
├── docker-compose.yml
└── api/
    ├── Dockerfile
    ├── requirements.txt
    └── app.py
```

`api/requirements.txt`:
```
Flask==3.0.3
redis==5.0.8
```

`api/app.py`:
```python
import os, redis
from flask import Flask, jsonify

r = redis.Redis(host=os.getenv("REDIS_HOST","redis"), port=6379)
app = Flask(__name__)

@app.get("/")
def ix():
    r.incr("hits")
    return jsonify(hits=int(r.get("hits") or 0))

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

`api/Dockerfile`:
```Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY app.py .
EXPOSE 5000
CMD ["python","app.py"]
```

`docker-compose.yml`:
```yaml
services:
  redis:
    image: redis:7-alpine
    healthcheck:
      test: ["CMD", "redis-cli", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5

  api:
    build: ./api
    environment:
      - REDIS_HOST=redis
      - FLASK_ENV=production
    ports:
      - "5000:5000"
    depends_on:
      redis:
        condition: service_healthy
```

**Proba:**
```bash
cd compose/02-env-depends
docker compose up --build
# http://localhost:5000 → {"hits":1}
```

**Puntos clave:** `depends_on` con condicións, env en runtime vs build args.  
**Criterios de éxito:** API arrinca cando Redis está *healthy* e incrementa `hits`.

## C) Volumes nomeados, datos persistentes e `.env`
**Que vas facer:** Postgres con persistencia en volume e `POSTGRES_PASSWORD` nun `.env`.

**Estrutura** (`compose/03-postgres/`):
```
compose/03-postgres/
├── docker-compose.yml
└── .env
```

`.env`:
```
POSTGRES_PASSWORD=supersegredo
```

`docker-compose.yml`:
```yaml
services:
  db:
    image: postgres:16-alpine
    ports: ["5432:5432"]
    environment:
      - POSTGRES_PASSWORD=${POSTGRES_PASSWORD}
    volumes:
      - pgdata:/var/lib/postgresql/data
volumes:
  pgdata:
```

**Proba:**
```bash
cd compose/03-postgres
docker compose --env-file .env up -d
# conectar con cliente psql/gui → datos persisten tras recreación
```

**Puntos clave:** diferenza volume nomeado vs bind mount, backups.  
**Criterios de éxito:** datos persisten tras `down` e nova subida.

## D) Redes, perfís e restart
**Que vas facer:** illar comunicación en redes separadas, activar servizos opcionais con *profiles* e configurar `restart`.

**Estrutura** (`compose/04-net-profiles/`):
```
compose/04-net-profiles/
└── docker-compose.yml
```

`docker-compose.yml`:
```yaml
networks:
  frontend: {}
  backend: {}

services:
  web:
    image: nginx:1.27-alpine
    ports: ["8080:80"]
    networks: [frontend]
    restart: unless-stopped

  api:
    build: ../02-env-depends/api
    networks: [frontend, backend]

  redis:
    image: redis:7-alpine
    networks: [backend]
    profiles: [cache]
```

**Probas:**
```bash
cd compose/04-net-profiles
docker compose up --build
docker compose --profile cache up -d redis
docker network inspect compose04-net-profiles_frontend
docker network inspect compose04-net-profiles_backend
```

**Puntos clave:** service discovery por nome, perfís para dev/test.  
**Criterios de éxito:** illamento correcto e arranque selectivo con perfís.

## E) Configs, secrets e límites locais
**Que vas facer:** montar configuración en *bind mount*, xestionar secrets en Compose (modo local) e comentar límites de recursos.

**Estrutura** (`compose/05-configs-secrets/`):
```
compose/05-configs-secrets/
├── docker-compose.yml
├── config/
│   └── nginx.conf
└── secrets/
    └── api_key.txt   # non subir a repo
```

`docker-compose.yml`:
```yaml
services:
  web:
    image: nginx:1.27-alpine
    ports: ["8080:80"]
    volumes:
      - ./config/nginx.conf:/etc/nginx/nginx.conf:ro
    environment:
      - API_KEY_FILE=/run/secrets/api_key
    secrets:
      - api_key

secrets:
  api_key:
    file: ./secrets/api_key.txt
```

`config/nginx.conf` 
```nginx
# user nginx;  # opcional (ou elimina a directiva)
worker_processes  1;

events { worker_connections 1024; }

http {
    # Sen formato de log personalizado para evitar 'main'
    access_log  /var/log/nginx/access.log;

    server {
        listen 8080;
        server_name _;

        root /usr/share/nginx/html;
        index index.html;

        location /health { return 200 'ok'; }

        location / { try_files $uri $uri/ =404; }
    }
}
```

**Nota:** `deploy.resources` aplica en Swarm; en local, límites finos aplícanse vía CLI/daemon.

**Criterios de éxito:** Nginx arrinca coa configuración montada e o segredo é accesible dentro do contedor.

## F) Escalado e logs
**Que vas facer:** escalar un servizo e observar logs das réplicas.

**Probas (reuse de B):**
```bash
cd compose/02-env-depends
docker compose up -d --build
docker compose up -d --scale api=3
docker compose logs -f api
```

**Puntos clave:** non hai balanceo automático; precisa proxy (Nginx/Traefik) para repartir tráﬁco.  
**Criterios de éxito:** 3 contedores `api` activos e logs diferenciados por instancia.
