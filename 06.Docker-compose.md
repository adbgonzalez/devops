# Docker Compose: Introducción y uso básico

## 1. Qué es Docker Compose

**Docker Compose** es una herramienta que permite **definir y ejecutar aplicaciones multicontenedor** mediante un único archivo de configuración YAML (`docker-compose.yml`).

En lugar de ejecutar varios comandos `docker run` manualmente, con Compose puedes **declarar servicios, redes y volúmenes** en un solo archivo y levantar todo el entorno con:

```bash
docker compose up
```

---

## 2. Para qué sirve

- **Organizar contenedores relacionados** (por ejemplo, una app web + base de datos).  
- **Automatizar despliegues locales** y reproducibles.  
- **Definir configuraciones complejas** (puertos, variables de entorno, volúmenes, etc.) en un solo documento.  
- **Evitar errores humanos** y facilitar la colaboración entre desarrolladores.  

---

## 3. Sintaxis básica del archivo `docker-compose.yml`

Estructura general:

```yaml
version: "3.9"        # Versión de la sintaxis de Docker Compose
services:             # Lista de servicios (cada uno es un contenedor)
  nombre_servicio:
    image: imagen:etiqueta
    container_name: nombre_contenedor
    ports:
      - "host:contenedor"
    environment:
      - VARIABLE1=valor1
    volumes:
      - ./ruta_local:/ruta_contenedor
    depends_on:
      - otro_servicio
volumes:              # (opcional) Definición de volúmenes persistentes
networks:             # (opcional) Definición de redes personalizadas
```

**Elementos principales:**

| Clave | Explicación |
|--------|-------------|
| `version` | Define la versión de la especificación de Docker Compose. |
| `services` | Cada servicio representa un contenedor. |
| `image` | Indica la imagen que se va a usar. |
| `build` | Permite construir una imagen a partir de un Dockerfile local. |
| `ports` | Mapea puertos del host con el contenedor. |
| `environment` | Añade variables de entorno al contenedor. |
| `volumes` | Define volúmenes compartidos (para persistencia o código). |
| `depends_on` | Indica dependencias entre servicios (ordena el arranque). |

## 4. Ejemplo 1: Servidor web simple con Nginx

### Estructura de directorios

```
/compose-web
├── docker-compose.yml
└── index.html
```

### index.html

```html
<!DOCTYPE html>
<html>
<head><title>Docker Compose</title></head>
<body><h1>¡Bienvenido al servidor Nginx con Docker Compose!</h1></body>
</html>
```

### docker-compose.yml

```yaml
version: "3.9"
services:
  web:
    image: nginx:alpine
    container_name: web_nginx
    ports:
      - "8080:80"
    volumes:
      - ./index.html:/usr/share/nginx/html/index.html
```

### Ejecución

```bash
docker compose up -d
```

Abre el navegador y visita:  
👉 [http://localhost:8080](http://localhost:8080)

Para detener y eliminar los contenedores:
```bash
docker compose down
```

## 5. Ejemplo 2: Aplicación web con Python y base de datos MySQL

Este ejemplo muestra cómo **varios servicios pueden trabajar juntos**.

### Estructura del proyecto

```
/compose-flask-mysql
├── app
│   ├── app.py
│   ├── requirements.txt
│   └── Dockerfile
└── docker-compose.yml
```

### app/app.py

```python
from flask import Flask
import os, mysql.connector

app = Flask(__name__)

@app.route('/')
def index():
    db = mysql.connector.connect(
        host="db",
        user="root",
        password=os.environ.get("MYSQL_ROOT_PASSWORD"),
        database="demo"
    )
    cursor = db.cursor()
    cursor.execute("SELECT '¡Docker Compose funcionando!'")
    return cursor.fetchone()[0]

if __name__ == "__main__":
    app.run(host="0.0.0.0", port=5000)
```

### app/requirements.txt

```
Flask==3.0.0
mysql-connector-python==9.1.0
```

### app/Dockerfile

```Dockerfile
FROM python:3.12-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
CMD ["python", "app.py"]
```

### docker-compose.yml

```yaml
version: "3.9"
services:
  web:
    build: ./app
    container_name: flask_app
    ports:
      - "5000:5000"
    environment:
      - MYSQL_ROOT_PASSWORD=1234
    depends_on:
      - db

  db:
    image: mysql:8.0
    container_name: mysql_db
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: 1234
      MYSQL_DATABASE: demo
    volumes:
      - db_data:/var/lib/mysql

volumes:
  db_data:
```

### Ejecución

```bash
docker compose up -d
```

Luego, accede en:  
👉 [http://localhost:5000](http://localhost:5000)

Verás el mensaje:  
`¡Docker Compose funcionando!`

Para detener y limpiar todo:

```bash
docker compose down -v
```

## 6. Resumen de comandos principales

| Comando | Función |
|----------|----------|
| `docker compose up` | Inicia todos los servicios definidos. |
| `docker compose up -d` | Inicia en segundo plano (detached). |
| `docker compose down` | Detiene y elimina contenedores y redes. |
| `docker compose ps` | Lista los servicios activos. |
| `docker compose logs -f` | Muestra los logs en tiempo real. |
| `docker compose build` | Construye imágenes definidas con `build`. |
| `docker compose exec <servicio> bash` | Abre una shell dentro de un servicio. |

---

## 7. Buenas prácticas

- Usar versiones **estables y específicas** de las imágenes (`nginx:alpine`, `mysql:8.0`, etc.).  
- No guardar contraseñas en el archivo, usar `.env` si es necesario.  
- Definir volúmenes para **persistir datos** de bases de datos.  
- Añadir `depends_on` para ordenar la ejecución de los servicios.  
- Usar `docker compose down -v` para limpiar volúmenes y redes cuando hagas pruebas.
