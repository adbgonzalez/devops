# Dockerfile: creación de imágenes personalizadas (de 0 a avanzado)

Referencia oficial: https://docs.docker.com/engine/reference/builder/

---

## 1. Qué es un Dockerfile

Un Dockerfile es un archivo de texto que define paso a paso cómo crear una imagen personalizada de Docker.
Cada línea contiene una instrucción, y Docker ejecutará esas instrucciones de arriba hacia abajo para construir una imagen.

Cuando ejecutas:

```bash
docker build -t nombre_imagen .
```

Docker lee el Dockerfile, ejecuta cada paso y guarda el resultado en capas reutilizables.

---

## 2. Primeros ejemplos: “Hello World” 
### 2.1. Usando sh
Imagen que simplemente imprime un mensaje por pantalla.

```Dockerfile
FROM alpine:3.20
CMD ["sh", "-c", "echo '¡Hola mundo desde Docker con Alpine!'"]
```
Construcción y ejecución:
```bash
docker build -t hola-alpine .
docker run --rm hola-alpine

```
### 2.2. "Hello World" en Python

Este es el ejemplo más sencillo posible: una imagen que simplemente imprime un mensaje.

Dockerfile
```Dockerfile
FROM python:3.12-slim

WORKDIR /app
COPY app.py .

CMD ["python", "app.py"]
```

app.py
```python
print("¡Hola, Docker! Este es mi primer contenedor.")
```

Construcción y ejecución
```bash
docker build -t hola:v1 .
docker run --rm hola:v1
```

## 3. Ejemplo básico con dependencias (requirements.txt)

Ahora añadimos dependencias de Python (por ejemplo Flask) y ejecutamos un pequeño servidor web.

Estructura del proyecto
```
/proyecto
├── Dockerfile
├── app.py
└── requirements.txt
```

requirements.txt
```
Flask==3.0.0
```

app.py
```python
from flask import Flask
app = Flask(__name__)

@app.route('/')
def inicio():
    return "¡Hola mundo desde Flask y Docker!"

if __name__ == '__main__':
    app.run(host="0.0.0.0", port=5000)
```

Dockerfile
```Dockerfile
FROM python:3.12-slim

WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

COPY . .

EXPOSE 5000
CMD ["python", "app.py"]
```

Comandos
```bash
docker build -t flask-basic:v1 .
docker run -d -p 5000:5000 flask-basic:v1
```

## 4. Cómo funciona el proceso de construcción

1. Docker lee el Dockerfile de arriba a abajo.  
2. Cada instrucción (FROM, RUN, COPY, etc.) genera una capa.  
3. Las capas se guardan en caché para acelerar futuras construcciones.  
4. El resultado es una imagen lista para crear contenedores.

Si cambias una línea superior (por ejemplo un RUN), la caché de las siguientes capas se invalida.

---

## 5. Instrucciones más habituales

| Instrucción | Descripción | Ejemplo |
|-------------|-------------|----------|
| FROM | Imagen base | FROM ubuntu:22.04 |
| RUN | Ejecuta comandos en el proceso de build | RUN apt-get install -y python3 |
| COPY | Copia archivos del host al contenedor | COPY . /app |
| WORKDIR | Define el directorio de trabajo | WORKDIR /app |
| ENV | Define variables de entorno | ENV PORT=5000 |
| EXPOSE | Documenta el puerto usado por la app | EXPOSE 8080 |
| USER | Define el usuario de ejecución | USER www-data |
| CMD | Comando por defecto al iniciar | CMD ["python", "app.py"] |
| ENTRYPOINT | Comando fijo principal | ENTRYPOINT ["python"] |
| ARG | Variable disponible durante el build | ARG VERSION=1.0 |
| HEALTHCHECK | Prueba periódica de salud | HEALTHCHECK CMD curl -f http://localhost:5000/ || exit 1 |

## 6. Scripts de inicio (start.sh)

Se puede usar un script de shell para iniciar servicios o realizar tareas previas antes de lanzar la aplicación.

start.sh
```bash
#!/usr/bin/env bash
set -e
echo "Iniciando aplicación..."
exec "$@"
```

Dockerfile
```Dockerfile
FROM python:3.12-slim
WORKDIR /app

COPY requirements.txt .
RUN pip install -r requirements.txt

COPY . .

RUN chmod +x start.sh
ENTRYPOINT ["./start.sh"]
CMD ["python", "app.py"]
```

## 7. Multi-stage build (optimización y tamaño reducido)

```Dockerfile
FROM python:3.12 AS builder
WORKDIR /wheels
COPY requirements.txt .
RUN pip wheel --wheel-dir=/wheels -r requirements.txt

FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /wheels /wheels
RUN pip install --no-cache-dir --no-index --find-links=/wheels -r /wheels/requirements.txt
COPY . .
CMD ["python", "app.py"]
```

---

## 8. Usuario no root (buena práctica)

```Dockerfile
FROM python:3.12-slim

RUN adduser --system appuser
WORKDIR /app
COPY . .

RUN pip install --no-cache-dir -r requirements.txt
USER appuser

CMD ["python", "app.py"]
```

---

## 9. HEALTHCHECK y variables de entorno

```Dockerfile
FROM python:3.12-slim

ENV FLASK_ENV=production PORT=5000

WORKDIR /app
COPY . .
RUN pip install -r requirements.txt

EXPOSE $PORT
HEALTHCHECK --interval=30s --timeout=3s CMD curl -f http://127.0.0.1:$PORT/ || exit 1

CMD ["python", "app.py"]
```

## 10. .dockerignore

```
__pycache__/
*.pyc
.venv/
.git/
*.log
```

Evita copiar archivos innecesarios al contenedor, reduciendo el tamaño de la imagen.

---

## 11. Comandos útiles de Docker

```bash
docker build -t app:v1 .
docker build -t app:v2 --no-cache .
docker run --rm -p 8080:5000 app:v1
docker run -it app:v1 /bin/bash
docker logs -f app
```

---

## 12. Mejores prácticas

- Usa imágenes oficiales y versionadas (por ejemplo python:3.12-slim).
- Evita instalar paquetes innecesarios.
- Agrupa instalaciones en pocas capas.
- Usa usuario no root.
- Define HEALTHCHECK.
- Usa .dockerignore.
- Reutiliza caché instalando dependencias antes de copiar el código.

---

## 13. Flujo completo de desarrollo y producción

```bash
# Desarrollo
docker build -t webapp:dev .
docker run --rm -p 5000:5000 -v "$PWD":/app webapp:dev

# Producción
docker build -t webapp:prod --pull .
docker run -d -p 8000:8000 webapp:prod
```
