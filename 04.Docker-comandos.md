# Guía práctica de comandos Docker 

## Detener y eliminar contenedores

```bash
# Detener todos los contenedores actualmente en ejecución
docker stop $(docker ps -a -q)

# Eliminar todos los contenedores (incluso los detenidos)
docker rm -f $(docker ps -a -q)

# Eliminar todas las imágenes disponibles en el sistema
docker rmi -f $(docker images -a -q)
```

---

## Trabajar con imágenes

Sitios útiles:

- [Docker Hub](https://hub.docker.com/)
- [dive (inspección de capas)](https://github.com/wagoodman/dive)

### Buscar imágenes

```bash
docker images                         # Lista de imágenes descargadas localmente
docker search nginx                   # Busca imágenes públicas con ese nombre
docker search --help                  # Muestra ayuda para el comando search
docker search -f is-official=true nginx  # Busca solo imágenes oficiales
docker search --filter=stars=20 nginx     # Imágenes con más de 20 estrellas
docker search adbgonzalez             # Busca imágenes de un usuario concreto
```

### Descargar imágenes

```bash
docker pull nginx                     # Descarga la última versión de Nginx
docker pull httpd                     # Descarga la imagen de Apache HTTP Server
docker pull mysql:5.7                 # Descarga versión específica de MySQL
docker pull mysql                     # Descarga la última versión disponible
docker pull adbgonzalez/kafka:3.9     # Descarga imagen personalizada de un usuario
```

### Inspección de imágenes

```bash
docker history nginx                  # Muestra las capas de una imagen
docker inspect nginx                  # Información detallada (JSON)
docker rmi nginx                      # Eliminar una imagen
docker rmi -f nginx                   # Forzar la eliminación
docker rmi --help                     # Ayuda sobre el comando rmi
```

Ruta local de almacenamiento de imágenes:

```bash
/var/lib/docker/image
```

## Lanzar contenedores (run/create)

```bash
docker run --help                     # Ayuda sobre el comando run
docker create --help                  # Ayuda sobre el comando create

docker run -dti httpd                 # Crea e inicia un contenedor con Apache (modo interactivo + terminal)
docker run -dti --rm --name web1 httpd   # Contenedor efímero con nombre “web1”
docker run -dti --name web-2 httpd echo hola  # Ejecuta un comando específico

docker create --rm --name web-create httpd   # Crea un contenedor sin arrancar
docker start web-create               # Inicia el contenedor creado

docker container run -dti --rm --name web3 httpd  # Versión extendida del comando run
docker run -dti --name web2 nginx     # Arranca un servidor Nginx
docker run -dti nginx                 # Arranca Nginx sin nombre específico
docker run -dti --name bd2 -e MYSQL_ROOT_PASSWORD=000000 mysql  # Arranca una BD MySQL con contraseña definida

# Ejemplo que fallará por no establecer contraseña de root
docker run -dti --name bd3 mysql
```

### Acceder al contenedor

```bash
docker exec -ti bd2 /bin/bash         # Entrar en el contenedor “bd2” con una shell
# Una vez dentro:
mysql -u root -p                      # Acceder a la base de datos MySQL
```

```bash
docker exec -ti bd3 /bin/bash         # Intentar acceder a otro contenedor
docker inspect web1                   # Ver detalles del contenedor “web1”
```

## Ver contenedores

```bash
docker ps -a                          # Mostrar todos los contenedores (activos y detenidos)
docker ps -l                          # Mostrar el último contenedor creado
docker container ls --help            # Ayuda para el comando ls

```

## Interacción y gestión de contenedores

```bash
docker inspect web1                   # Información detallada de un contenedor
docker exec -ti web1 /bin/bash        # Acceder a la shell de un contenedor activo
docker stop nombre-contenedor         # Detener un contenedor
docker start nombre-contenedor        # Arrancar un contenedor detenido
docker restart nombre-contenedor      # Reiniciar un contenedor
docker pause nombre-contenedor        # Pausar procesos de un contenedor
docker unpause nombre-contenedor      # Reanudar ejecución
docker rm nombre-contenedor           # Eliminar un contenedor
docker rm -f nombre-contenedor        # Forzar eliminación
docker logs nombre-contenedor         # Mostrar logs del contenedor
docker logs -f nombre-contenedor      # Seguir logs en tiempo real
docker logs -t nombre-contenedor      # Mostrar logs con marcas de tiempo
docker top contenedor1                # Ver procesos activos dentro de un contenedor
exit                                  # Salir de la shell de un contenedor
```

## Estadísticas y actualización de contenedores

```bash
docker stats                          # Mostrar consumo de recursos de los contenedores
docker update --help                  # Ayuda para cambiar recursos de un contenedor
docker update -m 512m --memory-swap -1 web1   # Limita la memoria del contenedor web1 a 512MB
```

### Opciones de `docker update`

```text
Usage:  docker update [OPTIONS] CONTAINER [CONTAINER...]

Update configuration of one or more containers

Options:
  --blkio-weight uint16        Block IO weight (10–1000)
  --cpu-period int             CPU CFS period
  --cpu-quota int              CPU CFS quota
  --cpu-rt-period int          Real-time period
  --cpu-rt-runtime int         Real-time runtime
  -c, --cpu-shares int         CPU shares
  --cpus decimal               Number of CPUs
  --cpuset-cpus string         Allowed CPUs (e.g. 0-3)
  --cpuset-mems string         Allowed memory nodes
  --kernel-memory bytes        Kernel memory limit
  -m, --memory bytes           Memory limit
  --memory-reservation bytes   Soft memory limit
  --memory-swap bytes          Swap limit ('-1' = unlimited)
  --pids-limit int             PIDs limit (-1 = unlimited)
  --restart string             Restart policy
```

Ejemplo de uso:

```bash
docker run -dti --name web1 httpd     # Crea contenedor
docker ps -a                          # Comprueba que está en ejecución
docker update -m 256m --memory-swap -1 web1  # Limita a 256 MB de RAM
```

## Políticas de reinicio

```text
--restart:

off              → No reiniciar
on-failure       → Reiniciar solo en caso de error
always           → Reiniciar siempre que se detenga
unless-stopped   → Reiniciar salvo que se detuviese explícitamente
```

Ejemplo:

```bash
docker run -dtiP --name web5 --restart always nginx
docker run -dti -p 8084:80 --name web1 --restart unless-stopped httpd
```

-u         → Define el usuario que ejecuta los comandos en el contenedor

## Publicar servicios y NAT de puertos

```bash
docker run -dtiP --name web11 httpd   # Publica automáticamente los puertos
docker run -dti -p 8085:80 --name web2 nginx  # Expone puerto 8085 del host
docker run -dti -p 3307:3306 --name bd2 -e MYSQL_ROOT_PASSWORD=000000 mysql  # Exposición manual de puerto MySQL

iptables -t nat -L DOCKER -v -n       # Ver reglas de NAT creadas por Docker
docker ps -a                          # Ver puertos asignados
docker port web11                     # Consultar puertos expuestos de un contenedor
```

Accede desde el navegador:

```
http://192.168.33.10:PUERTO
```

```text
-P  → Publica todos los puertos disponibles de forma automática
-p  → Publicación manual de un puerto (error si ya está en uso)
```

## Exposición de rangos de puertos

```Dockerfile
EXPOSE 7000-8000                     # Declaración en el Dockerfile
```

```bash
docker run --expose=7000-8000        # Exposición sin mapeo externo
docker run -p 7000-8000:7000-8000 imagen-docker  # Mapeo directo host ↔ contenedor
```

## Lanzamiento de contenedores

Estos comandos permiten crear y ejecutar contenedores de forma rápida a partir de imágenes existentes.

```bash
# Crea y ejecuta un contenedor en segundo plano (modo detached)
# El parámetro -P publica automáticamente todos los puertos expuestos
docker run -dtiP --name web2-lab httpd

# Crea un contenedor de Nginx, publicando manualmente el puerto 81 del host al 80 del contenedor
docker run -dti --name web3 -p 81:80 nginx
```

docker ps -a                   # Mostrar todos los contenedores (activos y detenidos)
iptables -t nat -L DOCKER -v -n  # Ver las reglas de NAT creadas por Docker
```

IP de ejemplo del contenedor:

```

## Copias de seguridad de imágenes

Las copias de seguridad permiten exportar y guardar imágenes localmente para reutilizarlas o transportarlas.

```bash
docker images | grep httpd      # Comprobar si la imagen httpd existe
docker save -o httpd.tar httpd  # Guardar la imagen httpd en un archivo TAR
docker rmi httpd                # Eliminar la imagen localmente
docker images                   # Verificar que ya no aparece en la lista
```

### Importar copia de seguridad

Para restaurar una imagen previamente guardada:

```bash
docker load -i httpd.tar         # Cargar imagen desde el archivo TAR
docker images | grep httpd       # Confirmar que la imagen fue importada
```

## Convertir un contenedor en una imagen

Este proceso permite generar una nueva imagen a partir de un contenedor ya configurado manualmente.

```bash
# Crear un contenedor base CentOS con stack LAMP
docker run -dtiP --name centos6 docker.io/nickistre/centos-lamp

# Acceder al contenedor para personalizarlo (por ejemplo instalar Joomla)
docker exec -ti centos6 /bin/bash

# Crear una nueva imagen a partir del contenedor modificado
docker commit -m "Intranet con Joomla" centos6 intranet-martes31

# Crear un nuevo contenedor desde la imagen resultante
docker run -ditP --name intranet1 intranet-martes31
```

Ejemplo de salida del comando `docker ps -l`:

```
CONTAINER ID   IMAGE       COMMAND            CREATED         STATUS       PORTS
f0bd287fae86   intranet    "supervisord -n"   7 seconds ago   Up 6 seconds 0.0.0.0:32774->22/tcp, 0.0.0.0:32773->80/tcp
```

### Etiquetar y ejecutar una imagen

Las etiquetas (*tags*) permiten versionar e identificar mejor las imágenes.

```bash
docker tag intranet intranet-martes31:v1      # Añadir etiqueta v1 a la imagen
docker run -ditP --name intranet1 intranet-martes31:v1   # Ejecutar la versión etiquetada
```

### Volúmenes montados

Los volúmenes permiten persistir datos (por ejemplo, BDs y archivos web) fuera del contenedor.

```bash
# Montar directorios locales como volúmenes
docker run -ditP --name intranet1 -v /bd2:/var/lib/mysql -v /web2:/var/www/html intranet-martes31

# Alternativa: usar volúmenes nombrados gestionados por Docker
docker run -ditP --name intranet1 -v bd2:/var/lib/mysql -v web2:/var/www/html intranet-martes31
```

- `/bd2` o `bd2`: volumen para datos de base de datos MySQL.  
- `/web2` o `web2`: volumen para archivos de la aplicación web.

## Publicar una imagen en Docker Hub

Para subir una imagen al repositorio público de DockerHub es necesario tener una cuenta e iniciar sesión.

```bash
# Añadir una etiqueta con el formato usuario/imagen
docker tag intranet-lunes19:v1 usuario/intranet

# Iniciar sesión con el usuario de DockerHub
docker login

# Subir la imagen al repositorio
docker push usuario/intranet

# Cerrar sesión
docker logout
```

### Otros comandos útiles

```bash
docker pull usuario/intranet                      # Descargar una imagen publicada
docker tag intranet miusuariodockerhub/intranet   # Renombrar antes de subir
cat /root/.docker/config.json                     # Comprobar credenciales guardadas
docker search usuario                             # Buscar imágenes de un usuario
docker search miusuariodockerhub                  # Buscar imágenes de otro usuario
```

## Trabajo con Volúmenes en Docker

Referencia oficial: [Volúmenes en Docker](https://docs.docker.com/storage/volumes/)

Un volumen en Docker es un **directorio especial persistente** asignado a un contenedor.  
Los volúmenes permiten **guardar datos de forma independiente al ciclo de vida de los contenedores**.

Normalmente se localizan en:

```
/var/lib/docker/volumes
```

---

### Comandos básicos de volumen

Docker ofrece un subcomando específico para gestionar volúmenes: `docker volume`.

```bash
docker volume

Usage:  docker volume COMMAND

Manage volumes

Commands:
  create      Create a volume
  inspect     Display detailed information on one or more volumes
  ls          List volumes
  prune       Remove all unused local volumes
  rm          Remove one or more volumes
```

Listar los volúmenes disponibles:

```bash
docker volume ls
```

Ejemplo de salida:

```
DRIVER               VOLUME NAME
local                0bf977f8de99b90fa1f2d7250415700cad4a6aaeff80c1e0c7bbd934aecaac19
```

---

### Uso de `-v` o `--mount`

Ambas opciones permiten montar volúmenes, pero `--mount` es más explícita y moderna.

#### Iniciar un contenedor con volumen

```bash
# Usando --mount
docker run -d --name devtest --mount source=myvol2,target=/app nginx:latest

# Usando -v (forma abreviada)
docker run -d --name devtest -v myvol2:/app nginx:latest
```

💡 Ambos crean el volumen automáticamente si no existe.

---

### Laboratorio: WordPress + MySQL con volumen persistente

En este ejemplo creamos un pequeño laboratorio con dos servicios: una base de datos y WordPress.

```bash
# Detener y eliminar contenedores existentes
docker stop $(docker ps -a -q)
docker rm -f $(docker ps -a -q)

# Crear directorio para persistencia de datos
mkdir /bd

# Lanzar contenedor MySQL con volumen persistente
docker run -dti --name servidor_mysql -e MYSQL_ROOT_PASSWORD=000000 -v /bd:/var/lib/mysql mysql:5.7

# Lanzar WordPress conectado a MySQL
docker run -dti --name servidor_wp -p 8000:80 --link servidor_mysql:mysql wordpress:5.6.2-php7.3
```

Acceso desde el navegador:

```
http://192.168.33.10:8000/
```

### Primera forma: Volúmenes automáticos

Cuando no se especifica una ruta local, Docker crea volúmenes automáticos.

```bash
docker run -dtiP --name centos6-lanp -v /var/www/html docker.io/nickistre/centos-lamp
docker inspect centos6-lanp
docker volume inspect <nombre_volumen>
```

Ruta típica de un volumen:

```
/var/lib/docker/volumes/<nombre_volumen>/_data
```

---

### Segunda forma: Volumen ligado a un directorio local

Esta opción es ideal para desarrollo, ya que permite editar archivos directamente en el host.

```bash
mkdir /web
cd /web
echo "prueba de volumen" > index.html

# Montar directorio local con acceso total
docker run -dtiP --name centos6-prueba-web -v /web:/var/www/html docker.io/nickistre/centos-lamp

# Montar el mismo directorio en modo lectura
docker run -dtiP --name centos6-prueba-web2 -v /web:/var/www/html:ro docker.io/nickistre/centos-lamp
```

- `/web` → Directorio del host con contenido web.  
- `/var/www/html` → Ruta donde el servidor web sirve los archivos.

---

### Tercera forma: Volumen nombrado + volumen ligado

Combina volúmenes persistentes creados por Docker con directorios del sistema anfitrión.

```bash
docker volume create --name webapp      # Crear volumen nombrado
docker volume ls                        # Ver lista de volúmenes
docker volume inspect webapp            # Ver detalles
```

Añadir contenido manualmente al volumen:

```bash
echo "prueba de volumen" > /var/lib/docker/volumes/webapp/_data/index.html
```

Lanzar contenedor con ambos volúmenes:

```bash
mkdir /web
docker run -dtiP --name centos6-pruebacreacion3 -v webapp:/var/www/html -v /web:/datos docker.io/nickistre/centos-lamp
docker inspect centos6-pruebacreacion3 | grep -A 5 -i mounts
docker exec -ti centos6-pruebacreacion3 /bin/bash
ls /datos
```

Eliminar contenedores detenidos (en estado *Exited*):

```bash
docker rm $(docker ps -a -f status=exited -q)
```

### Ejemplo con `--mount`

```bash
# Crear contenedor con volumen mediante --mount
docker run -d --name devtest --mount source=myvol2,target=/app nginx:latest

# Ver volúmenes disponibles e inspeccionar
docker volume ls
docker volume inspect myvol2
```

Comprobar montaje dentro del contenedor:

```bash
docker exec -ti devtest bash

```

### Volumen en modo lectura

Permite montar un volumen solo para lectura, impidiendo modificaciones en el contenedor.

```bash
# Forma larga
docker run -d --name=nginxtest --mount source=nginx-vol,destination=/usr/share/nginx/html,readonly nginx:latest

# Forma abreviada
docker run -d --name=nginxtest -v nginx-vol:/usr/share/nginx/html:ro nginx:latest
```

Explicación:

- `source` → Nombre del volumen.  
- `destination` → Ruta dentro del contenedor.  
- `readonly` → Indica montaje en modo solo lectura.
