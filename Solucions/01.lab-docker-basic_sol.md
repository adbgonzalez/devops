# Laboratorio: comandos básicos de Docker (docker run y afines)

Este laboratorio sirve para practicar los comandos fundamentales de Docker. 
Las imágenes y versiones están especificadas en cada paso para garantizar reproducibilidad.

## 1. Verificar el entorno Docker
Objetivo: confirmar que Docker está correctamente instalado y operativo.
```bash
docker version
docker info
```

## 2. Descargar una imagen de Alpine Linux
Objetivo: descargar manualmente la imagen base alpine:3.20 desde Docker Hub sin ejecutarla.
```bash
docker pull alpine:3.20
```

## 3. Ejecutar un contenedor efímero
Objetivo: lanzar un contenedor de Alpine que muestre un mensaje y se elimine al salir. 
Imagen: alpine:3.20
```bash
docker run --rm alpine:3.20 echo "¡Hola desde Alpine en Docker!"
```

## 4. Abrir una sesión interactiva
Objetivo: entrar en un contenedor Alpine para ejecutar comandos Linux manualmente. 
Imagen: alpine:3.20
```bash
docker run --rm -it alpine:3.20 sh
```

## 5. Ejecutar un servidor Nginx básico
Objetivo: levantar un servidor web usando la imagen nginx:1.27-alpine. 
El contenedor se llama web1 y expone el puerto 8080 del host hacia el 80 del contenedor.
```bash
docker run -d --name web1 -p 8080:80 nginx:1.27-alpine
```

## 6. Listar contenedores activos
Objetivo: comprobar que el contenedor web1 está en ejecución.
```bash
docker ps
```

## 7. Ver los registros de un contenedor
Objetivo: consultar la salida de Nginx en el contenedor web1.
```bash
docker logs web1
```

## 8. Inspeccionar un contenedor
Objetivo: obtener información detallada del contenedor web1 (configuración, IP, montajes...).
```bash
docker inspect web1
docker inspect -f '{{ .NetworkSettings.IPAddress }}' web1
```

## 9. Entrar en el contenedor en ejecución
Objetivo: acceder a la shell de web1 para explorar el sistema de archivos interno.
```bash
docker exec -it web1 sh
```

## 10. Copiar archivos al contenedor
Objetivo: añadir una página personalizada dentro de web1.
```bash
echo "<h1>¡Bienvenido a mi sitio!</h1>" > index.html
docker cp index.html web1:/usr/share/nginx/html/index.html
```

## 11. Ejecutar otro Nginx en puerto diferente
Objetivo: levantar otro servidor web (web2) en el puerto 8081.
```bash
docker run -d --name web2 -p 8081:80 nginx:1.27-alpine
```

## 12. Usar variables de entorno
Objetivo: lanzar un contenedor de Alpine imprimiendo el contenido de una variable. 
Variable: GREET=Hola
```bash
docker run --rm -e GREET="Hola" alpine:3.20 sh -c 'echo "$GREET, mundo!"'
```

## 13. Servir archivos locales (bind mount)
Objetivo: servir un archivo HTML del host en un contenedor Nginx. 
Imagen: nginx:1.27-alpine, contenedor: web3, puerto: 8082. Directorio desde el que nginx sirve los `html`s: /usr/share/nginx/html.
```bash
mkdir -p site && echo "<h1>Contenido local</h1>" > site/index.html
docker run -d --name web3 -p 8082:80 -v "./site:/usr/share/nginx/html:ro" nginx:1.27-alpine
```

## 14. Volumen nombrado persistente
Objetivo: crear un volumen permanente llamado webdata y usarlo en web4. 
Imagen: nginx:1.27-alpine, puerto: 8083. Entrar en el contenedor y crear un index.html, eliminar el contenedor y volver a crearlo para comprobar la persistencia.
```bash
docker volume create webdata
docker run -d --name web4 -p 8083:80 -v webdata:/usr/share/nginx/html nginx:1.27-alpine
docker exec web4 sh -c 'echo "<h1>Página persistente</h1>" > /usr/share/nginx/html/index.html'
docker stop web4 && docker rm web4
docker run -d --name web4b -p 8083:80 -v webdata:/usr/share/nginx/html nginx:1.27-alpine
```

## 15. Limitar recursos de CPU y memoria
Objetivo: ejecutar un contenedor con recursos limitados. 
Imagen: alpine:3.20, nombre: limited. Limita la CPU a 0.5, la memoria a 256 MB (256m) y ejecuta el comando sleep 300.
```bash
docker run -d --name limited --cpus="0.5" --memory="256m" alpine:3.20 sh -c "sleep 300"
```

## 16. Consultar volúmenes y redes disponibles
Objetivo: listar todos los volúmenes y redes creados.
```bash
docker volume ls
docker network ls
```

## 17. Comunicación entre contenedores en una red
Objetivo: crear una red llamada appnet y conectar dos contenedores. 
redis-server → servicio Redis (imagen redis:7-alpine)  
redis-client → contenedor Alpine que ejecuta redis-cli ping: apk add --no-cache redis && redis-cli -h redis-server ping
```bash
docker network create appnet
docker run -d --name redis-server --network appnet redis:7-alpine
docker run --rm --network appnet alpine:3.20 sh -c "apk add --no-cache redis && redis-cli -h redis-server ping"
```
Alternativa más simple: usar una imagen Alpine y el comando sleep, y conectarse a ella mediante ping.
```bash
docker run -d --rm --name host1 --network appnet alpine:3.20 sh -c "sleep 300"
docker run --rm --name host2 --network appnet alpine:3.20 sh -c "ping host1"
```

## 18. Eliminar contenedores y volúmenes
Objetivo: limpiar recursos de práctica.
```bash
docker rm -f web1 web2 web3 web4b limited redis-server
docker volume rm webdata
docker network rm appnet
```

## 19. Limpieza final
Objetivo: eliminar recursos no usados y liberar espacio.
```bash
docker system prune -f
```
