# Tarefa: facer máis seguro un Docker Compose

**Módulo:** Posta en Produción Segura  
**Unidade:** Despregamento seguro de aplicacións  
**Puntuación máxima:** 10 puntos

## 1. Preparación

Precisas Docker e Docker Compose v2. Crea unha carpeta nova `tarefa-compose` cos seguintes ficheiros, sen reutilizar volumes doutras prácticas.

### `docker-compose.yml`

```yaml
services:
  web:
    image: nginx
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html

  db:
    image: postgres
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: contrasinal_de_proba
      POSTGRES_DB: tarefa
    volumes:
      - pgdata:/var/lib/postgresql

volumes:
  pgdata:
```

### `html/index.html`

```html
<!doctype html>
<html lang="gl">
  <head>
    <meta charset="utf-8">
    <title>Práctica de Docker Compose</title>
  </head>
  <body>
    <h1>Ola desde Compose!</h1>
    <p>Os servizos funcionan. Agora toca revisar a seguridade.</p>
  </body>
</html>
```

**Escenario:** só necesitas acceder á web desde o propio equipo e administrar PostgreSQL mediante `docker compose exec`. A web é estática e non se conecta á base de datos. Emprega unicamente o contrasinal ficticio indicado.

A ruta de datos está preparada para PostgreSQL 18 e posteriores. Non reutilices un proxecto de PostgreSQL 16: esta tarefa non inclúe migracións.

## 2. Traballo

### Estado inicial

Desde `tarefa-compose`, executa:

```bash
docker compose config --quiet
docker compose pull
docker compose up -d
docker compose ps
docker compose logs db
docker compose images
docker compose exec web nginx -v
docker compose exec db postgres --version
```

Garda as referencias, versións e identificadores das imaxes. Comproba a web en `http://localhost:8080/`. Cando PostgreSQL estea preparado, conecta por TCP:

```bash
docker compose exec db psql -h db -U postgres -d tarefa -W
```

Introduce o contrasinal cando o solicite e executa:

```sql
CREATE TABLE comprobacion (id INTEGER PRIMARY KEY, mensaxe TEXT);
INSERT INTO comprobacion VALUES (1, 'Docker Compose funciona');
SELECT * FROM comprobacion;
\q
```

### Análise e corrección

1. Identifica **catro debilidades de seguridade** no despregamento inicial.
2. Para cada unha, explica a consecuencia e aplica unha corrección mediante Compose e os ficheiros de configuración necesarios.
3. Achega unha proba antes e despois de cada cambio que permita verificar a corrección. Podes empregar `docker compose config`, `docker compose ps`, `docker inspect` e comprobacións dentro dos contedores. Non mostres o contido do segredo nas evidencias.
4. Valida a configuración final, recrea os contedores e comproba o funcionamento e a persistencia.

**Condicións:**

- Mantén os dous servizos, as imaxes oficiais, o HTML, o volume de datos e a súa ruta de montaxe. A web debe seguir accesible no porto `8080` do equipo.
- Para PostgreSQL, conserva a versión maior e a variante da imaxe inicial. Xustifica as versións finais e como revisarías e probarías futuras actualizacións de seguridade.
- Conserva o mesmo contrasinal ficticio: cambiar como se fornece non modifica o contrasinal dunha base de datos xa inicializada.
- Non crees Dockerfiles, non modifiques as imaxes nin instales ferramentas adicionais.
- Protexe o ficheiro local do segredo e exclúeo de Git; empregar un secret de Compose non cifra o ficheiro no disco.

Como apoio, consulta a [teoría de Docker Compose](../06.Docker-compose.md) e o [laboratorio](../Laboratorios/03.lab-compose.md).

### Comprobación final

```bash
docker compose config --quiet
docker compose down
docker compose up -d
docker compose ps
```

Non empregues `docker compose down -v`: eliminaría os datos que debes conservar.

Comproba que a web serve o HTML orixinal. Repite a conexión por TCP co contrasinal solicitado de forma interactiva e executa `SELECT * FROM comprobacion;`: debe conservar a fila inicial.

## 3. Entrega

Entrega a carpeta con:

- `docker-compose.yml` final e unha copia inicial como `docker-compose.inicial.yml`, só para comparar.
- O HTML, o `.gitignore` e os ficheiros de configuración necesarios.
- Un ficheiro de exemplo do segredo co valor ficticio e instrucións para copialo á ruta esperada. **Non entregues o ficheiro local do segredo.**
- Un `README.md` breve coas catro debilidades, as súas consecuencias e correccións, os pasos de execución e as evidencias antes e despois, incluíndo funcionamento e persistencia.
