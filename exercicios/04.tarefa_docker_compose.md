# Tarefa: facer máis seguro un Docker Compose

**Módulo:** Posta en Produción Segura  
**Unidade:** Despregamento seguro de aplicacións  
**Puntuación máxima:** 10 puntos

## Obxectivo

Analiza un despregamento que funciona, identifica tres problemas de seguridade e corrixe a configuración con cambios sinxelos. Xustifica brevemente as túas decisións e comproba que os servizos seguen funcionando.

Como apoio podes consultar a [teoría de Docker Compose](../06.Docker-compose.md) e os apartados A, C e E do [laboratorio](../Laboratorios/03.lab-compose.md): portos, montaxes, volumes persistentes e secrets.

## 1. Crea a estrutura inicial

Precisas Docker e Docker Compose v2. Crea unha carpeta chamada `tarefa-compose` e, dentro dela, os ficheiros seguintes. Copia o contido dos cadros de texto:

```text
tarefa-compose/
├── docker-compose.yml
└── html/
    └── index.html
```

### `docker-compose.yml`

```yaml
services:
  web:
    image: nginx:1.27-alpine
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html

  db:
    image: postgres:16-alpine
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: contrasinal_de_proba
      POSTGRES_DB: tarefa
    volumes:
      - pgdata:/var/lib/postgresql/data

volumes:
  pgdata:
```

### `html/index.html`

```html
<!doctype html>
<html lang="gl">
  <head>
    <meta charset="utf-8">
    <title>Práctica de Docker Compose</title>
  </head>
  <body>
    <h1>Ola desde Compose!</h1>
    <p>Os servizos funcionan. Agora toca revisar a seguridade.</p>
  </body>
</html>
```

O contrasinal é ficticio: non empregues credenciais reais. A web é estática e non se conecta á base de datos; comprobarás cada servizo por separado. O escenario é un equipo de prácticas no que só necesitas acceder á web desde o propio equipo e administrar PostgreSQL mediante `docker compose exec`.

## 2. Traballo que debes realizar

Desde a carpeta `tarefa-compose`, valida a configuración e arrinca os servizos:

```bash
docker compose config --quiet
docker compose up -d
docker compose ps
docker compose logs db
```

Abre `http://localhost:8080/`. Agarda a que PostgreSQL indique que está preparado para aceptar conexións e comproba o acceso por TCP:

```bash
docker compose exec db psql -h db -U postgres -d tarefa -W
```

Introduce o contrasinal de proba cando o solicite. Dentro de `psql`, executa:

```sql
CREATE TABLE comprobacion (id INTEGER PRIMARY KEY, mensaxe TEXT);
INSERT INTO comprobacion VALUES (1, 'Docker Compose funciona');
SELECT * FROM comprobacion;
\q
```

1. Analiza o Compose e o comportamento dos contedores. Identifica **tres problemas de seguridade** relacionados coa exposición dos servizos, os permisos da montaxe do HTML e a xestión do contrasinal.
2. Modifica o Compose e engade os ficheiros de configuración que consideres necesarios para corrixilos. Axusta a exposición dos portos ás necesidades do escenario e emprega **secrets de Compose** para o contrasinal, accesible só polo servizo que o precisa. Mover o valor a un `.env` e seguir inxectándoo como `POSTGRES_PASSWORD` non completa esta corrección.
3. Valida a nova configuración e recrea os contedores. Comproba cada corrección e que ambos os servizos seguen funcionando.
4. Explica brevemente cada problema detectado, a súa consecuencia e a solución aplicada.

Mantén os dous servizos, as imaxes indicadas, o contido da páxina e o volume de datos. A web debe seguir accesible no porto `8080` do equipo. Resolve a tarefa mediante Compose e ficheiros de configuración, sen crear Dockerfiles, modificar as imaxes nin instalar ferramentas adicionais.

Para o segredo, consulta a convención `POSTGRES_PASSWORD_FILE` da imaxe de PostgreSQL e a [documentación de secrets en Compose](https://docs.docker.com/compose/how-tos/use-secrets/). En Compose local, un secret baseado nun ficheiro non cifra ese ficheiro no disco: debes protexelo e excluílo do control de versións cun `.gitignore`.

**Importante:** PostgreSQL emprega o contrasinal de inicialización cando o directorio de datos está baleiro. Para esta tarefa, conserva o mesmo contrasinal ficticio ao cambiar a forma de fornecelo. Non elimines o volume para aplicar as correccións.

### Comprobacións que debes achegar

- **Exposición dos servizos:** mostra os portos publicados antes e despois. Xustifica a que interfaces do equipo queda vinculada a web e por que PostgreSQL xa non precisa un porto publicado. Podes empregar `docker compose ps` e `docker inspect` sobre os contedores.
- **Permisos do HTML:** proba a crear un ficheiro de comprobación desde o contedor, antes e despois do cambio:

  ```bash
  docker compose exec web touch /usr/share/nginx/html/proba-escritura.txt
  ```

  Inicialmente debería funcionar; coa corrección debe fallar por ser unha montaxe de só lectura. Elimina o ficheiro de proba da carpeta local `html/` despois da comprobación inicial. A páxina debe seguir visible.

- **Xestión do contrasinal:** achega evidencias de que o valor xa non figura no Compose nin nas variables de contorno configuradas no contedor mediante Docker. Comproba que o ficheiro do secret está dispoñible en `db` e non en `web`. Non abonda con montar o ficheiro: PostgreSQL debe estar configurado para lelo. Non inclúas o seu contido nas evidencias.
- **Funcionamento e persistencia:** comproba a web e repite a conexión por TCP a PostgreSQL co contrasinal solicitado de forma interactiva. Executa `SELECT * FROM comprobacion;` e verifica que conserva a fila inicial tras recrear os contedores.

Podes aplicar os cambios e comprobar a persistencia con:

```bash
docker compose config --quiet
docker compose down
docker compose up -d
docker compose ps
```

Non empregues `docker compose down -v` durante as probas: eliminaría o volume cos datos que debes conservar.

## 3. Entrega

Entrega a carpeta co `docker-compose.yml` final, o HTML, o `.gitignore` e os ficheiros de configuración que engadises. Conserva tamén unha copia do Compose inicial como `docker-compose.inicial.yml`, só para comparar; executa o proxecto co ficheiro final.

Non entregues o ficheiro local do segredo. Inclúe no seu lugar un ficheiro de exemplo co valor ficticio e indica como copialo á ruta esperada antes de arrincar.

Inclúe un `README.md` breve con:

- Os tres problemas de seguridade identificados e a súa consecuencia.
- A solución aplicada a cada problema, explicada nunha ou dúas frases.
- Os pasos para preparar o ficheiro do segredo e os comandos de execución e comprobación empregados.
- Evidencias dos resultados antes e despois dos cambios, do funcionamento dos dous servizos e da persistencia dos datos.

## Rúbrica de avaliación

Cada problema ten un valor máximo de **3 puntos**. O nivel acadado determina a porcentaxe desa puntuación:

| Ítem | Nivel 1 · 0 % | Nivel 2 · 40 % | Nivel 3 · 75 % | Nivel 4 · 100 % |
|---|---|---|---|---|
| **Exposición dos servizos · 3 puntos** | Non identifica o problema. | Identifica o problema correctamente, pero non aplica unha solución ou esta non é axeitada. | Identifica o problema e aplica unha solución axeitada, pero a explicación ou as evidencias son insuficientes. | Identifica o problema, limita a exposición segundo o escenario e xustifica a solución con evidencias correctas. |
| **Permisos da montaxe · 3 puntos** | Non identifica o problema. | Identifica o problema correctamente, pero non aplica unha solución ou esta non é axeitada. | Identifica o problema e aplica unha solución axeitada, pero a explicación ou as evidencias son insuficientes. | Identifica o problema, impide a escritura desde o contedor e xustifica a solución coa proba antes e despois. |
| **Xestión do contrasinal · 3 puntos** | Non identifica o problema. | Identifica o problema correctamente, pero non aplica unha solución ou esta non é axeitada. | Emprega un secret correctamente, pero a explicación, a exclusión do control de versións ou as evidencias son insuficientes. | Retira o valor do Compose e do contorno configurado, emprega un secret só en `db`, exclúe o ficheiro de Git e xustifica a solución con evidencias correctas. |

A puntuación por problema será de **0 / 1,20 / 2,25 / 3 puntos**, segundo o nivel acadado.

| Comprobación de funcionamento | Puntos |
|---|---:|
| Non demostra o funcionamento dos dous servizos e a persistencia dos datos despois dos cambios. | 0 |
| Achega unha comprobación da web, do acceso autenticado por TCP a PostgreSQL e da conservación da fila inicial despois de recrear os contedores. | 1 |

**Puntuación máxima: 3 + 3 + 3 + 1 = 10 puntos.**
