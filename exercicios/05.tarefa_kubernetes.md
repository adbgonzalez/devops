# Tarefa de revisión de manifestos Kubernetes

**Módulo:** Posta en Produción Segura  
**Puntuación máxima:** 10 puntos  
**Duración orientativa:** 45–60 minutos

Le os manifestos, responde as preguntas e fai os cambios pedidos. Podes consultar os [apuntamentos](../07.kubernetes.md) e o [laboratorio](../Laboratorios/04.lab-kubernetes.md).

**Non é necesario executar nada.** Podes probar os manifestos, pero non se piden capturas nin comandos e a execución non conta para a nota. Todos os contrasinais desta tarefa son ficticios.

## 1. Comprender o manifesto · 3 puntos

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpine
          ports:
            - containerPort: 80
---
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: ClusterIP
  selector:
    app: web
  ports:
    - port: 8080
      targetPort: 80
```

Responde brevemente:

1. Cantos Pods se pretenden manter e que imaxe utilizan? Sinala os campos correspondentes.
2. Como selecciona o Service os Pods? Sinala as etiquetas e o selector que relacionan ambos recursos.
3. Que significan `port: 8080` e `targetPort: 80` neste Service?
4. Se eliminamos un Pod, que ocorrerá? Que papel ten o Deployment?
5. Un compañeiro afirma: «Podo subir un Secret con credenciais reais a un repositorio público porque os valores están en base64». Ten razón? Explica por que.

**Avaliación:** preguntas 1–4, **0,5 puntos cada unha**; pregunta 5, **1 punto**. Na pregunta 5: 0,5 por explicar que base64 non é cifrado e 0,5 por explicar o risco de publicar as credenciais.

## 2. Detectar e corrixir problemas · 4 puntos

Este despregue debe cumprir estas condicións:

- O Service debe seleccionar os Pods de `web` e ser de tipo `ClusterIP`, para acceso interno.
- O contrasinal debe estar nun `Secret`, referenciado desde o Deployment.
- O contedor debe ter estes límites: CPU `200m` e memoria `128Mi`.

Hai **catro problemas** respecto destas condicións. Identifícaos, explica a consecuencia de cada un nunha frase e entrega o YAML corrixido. Mantén os nomes dos recursos e usa o contrasinal ficticio indicado. Podes usar `stringData` para definir o Secret; non se pide cifrar o ficheiro.

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: web-credentials
data:
  DB_PASSWORD: "contrasinal_de_proba"
---
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 2
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
        - name: nginx
          image: nginx:1.27-alpine
          ports:
            - containerPort: 80
          envFrom:
            - configMapRef:
                name: web-credentials
---
apiVersion: v1
kind: Service
metadata:
  name: web
spec:
  type: NodePort
  selector:
    app: backend
  ports:
    - port: 80
      targetPort: 80
```

Aquí só se practica como fornecer unha variable ao contedor: Nginx non utiliza `DB_PASSWORD` nin se conecta a unha base de datos.

**Avaliación:** cada problema vale **1 punto**: 0,25 por identificalo, 0,25 por explicar a consecuencia e 0,5 pola corrección. O cambio de ConfigMap a Secret e o da súa referencia contan como unha única corrección, que debe incluír ambos cambios.

## 3. Completar un fragmento · 3 puntos

Este fragmento pertence a un contedor dun Deployment. Existe un Secret chamado `app-secret` coa chave `DB_PASSWORD`. A aplicación atende peticións HTTP en `/` no porto `80`.

Substitúe os seis ocos `___` para obter o contrasinal dese Secret e configurar unha **readiness probe**. Non tes que escribir o resto do Deployment.

```yaml
env:
  - name: DB_PASSWORD
    valueFrom:
      ___:
        name: ___
        key: ___
readinessProbe:
  ___:
    path: ___
    port: ___
```

Banco de respostas: `secretKeyRef`, `configMapKeyRef`, `app-secret`, `DB_PASSWORD`, `httpGet`, `tcpSocket`, `/`, `80`, `8080`. Non tes que usalas todas.

**Avaliación:** cada oco correcto vale **0,5 puntos**.

## Entrega e nota

Entrega:

- Un documento coas respostas do apartado 1 e os catro problemas e consecuencias do apartado 2.
- O manifesto corrixido do apartado 2 e o fragmento completado do apartado 3, como ficheiros YAML ou bloques de código no mesmo documento.
