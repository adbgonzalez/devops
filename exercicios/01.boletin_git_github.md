# 🧾 Boletín de ejercicios sobre Git y GitHub

---

## 1. Configuración inicial de Git
**Objetivo:** Configurar Git por primera vez.  
**Instrucciones:**
1. Define tu nombre de usuario y correo electrónico global.  
2. Cambia el editor por defecto a **nano**.  
3. Configura el comportamiento de los finales de línea para Linux (`input`).  
4. Muestra la configuración actual.

---

## 2. Creación de un nuevo repositorio local
**Objetivo:** Iniciar un proyecto nuevo con control de versiones.  
**Instrucciones:**
1. Crea un directorio llamado `proyecto1` y accede a él.  
2. Inícialo como repositorio de Git.  
3. Crea un archivo `README.md` con un texto breve.  
4. Añádelo al *staging area* y realiza el primer commit.

---

## 3. Seguimiento de cambios
**Objetivo:** Comprender el flujo de *staging → commit*.  
**Instrucciones:**
1. Modifica el archivo `README.md`.  
2. Usa `git status` y `git diff` para ver los cambios.  
3. Añade los cambios y realiza un nuevo commit con un mensaje claro.  
4. Consulta el historial con el comando `git log`.

---

## 4. Trabajo con ramas
**Objetivo:** Crear y cambiar entre ramas.  
**Instrucciones:**
1. Crea una nueva rama llamada `feature-1`.  
2. Cambia a esa rama y crea un archivo `nota.txt` con un mensaje.  
3. Realiza un commit.  
4. Vuelve a la rama principal (`main`) y comprueba que el archivo no aparece.  
5. Haz un merge de la rama `feature-1` con `main`.  
6. Elimina la rama `feature-1`.

---

## 5. Clonación de un repositorio remoto
**Objetivo:** Practicar la clonación desde GitHub.  
**Instrucciones:**
1. Crea un repositorio vacío en GitHub llamado `practica1`.  
2. Clónalo en tu equipo local.  
3. Crea un archivo `autor.txt` con tu nombre.  
4. Añade, confirma y sube los cambios al remoto.

---

## 6. Subida de un proyecto local a GitHub
**Objetivo:** Enlazar un repositorio local con un remoto.  
**Instrucciones:**
1. En tu proyecto local (por ejemplo `proyecto1`), añade el remoto:  
   `https://github.com/usuario/proyecto1.git`.  
2. Renombra la rama principal a `main`.  
3. Sube el proyecto al remoto.  
4. Verifica en la web de GitHub que los archivos aparecen.

---

## 7. Deshacer cambios y restaurar versiones
**Objetivo:** Revertir modificaciones.  
**Instrucciones:**
1. Modifica el archivo `README.md`.  
2. Rechaza los cambios usando `git restore`.  
3. Realiza otro cambio y crea un commit erróneo.  
4. Corrige el mensaje de ese commit usando `git commit --amend`.  
5. Ejecuta `git reset --hard HEAD~1` para volver un commit atrás.

---

## 8. Uso de etiquetas (tags)
**Objetivo:** Crear versiones numeradas del proyecto.  
**Instrucciones:**
1. Crea una etiqueta llamada `v1.0` sobre el último commit.  
2. Lista las etiquetas existentes.  
3. Sube la etiqueta al repositorio remoto.  
4. Crea una nueva etiqueta `v1.1` y elimínala localmente.

---

## 9. Trabajo colaborativo con ramas
**Objetivo:** Simular un flujo de trabajo en equipo.  
**Instrucciones:**
1. Crea una nueva rama llamada `correccion-bug`.  
2. Realiza un cambio menor en un archivo y haz commit.  
3. Haz un merge de esa rama en `main`.  
4. Resuelve el posible conflicto de fusión si aparece.  
5. Elimina la rama después de completar el merge.

---

## 10. Creación de un fork y *pull request* 
**Objetivo:** Comprender el flujo colaborativo con GitHub.  
**Instrucciones:**
1. Realiza un **fork** de un repositorio público en GitHub.  
2. Clónalo en tu equipo local.  
3. Crea una rama llamada `mejora-docs` y añade una línea a un archivo.  
4. Realiza commit y sube la rama a tu fork.  
5. Desde GitHub, crea un **pull request** hacia el repositorio original.
