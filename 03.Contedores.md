## Motivación e Historia

- Resolver incompatibilidades entre entornos.  
- **Primeros pasos:**
  - *chroot (1979)*
  - *FreeBSD Jails (2000)*
  - *OpenVZ (2005)*
  - *LXC (2008)*
  - *LXD (2015)*
- **Docker** populariza los contenedores en *2013*.

---

## Ventajas de los contenedores

- Ligereza y velocidad  
- Portabilidad entre entornos  
- Aislamiento de procesos  
- Escalabilidad e integración con CI/CD  

---

## Inconvenientes de los contenedores

- Menor aislamiento que los hipervisores  
- Posibles riesgos de seguridad  
- Gestión compleja de volúmenes y persistencia  
- Dependencia del kernel Linux  

---

## Ciberseguridad y contenedores

### Riesgos
- Escape de contenedor  
- Imágenes inseguras  
- Permisos excesivos  

### Medidas
- Escaneo con **Trivy**, **Clair**  
- Ejecución **sin root**  
- Uso de **AppArmor**, **SELinux**

---

## Tecnologías actuales

- **Docker:** contenedores ligeros y populares  
- **Podman:** alternativa sin *daemon*  
- **LXC / LXD:** más cerca de una VM  
- **Kubernetes:** orquestación  
- **containerd, CRI-O:** motores backend  

---

## Comparativa Docker vs Podman

| **Aspecto** | **Docker** | **Podman** |
|--------------|-------------|-------------|
| Daemon | Requiere daemon | No requiere daemon |
| Ejecución | Se ejecuta como servicio en segundo plano | Se ejecuta directamente como proceso |
| Seguridad | Requiere permisos elevados | Puede ejecutarse como usuario sin root |
| Compatibilidad | Muy extendido | Compatible con imágenes y comandos de Docker |
| Integración | Docker Compose, Swarm | Podman Compose, integración con Kubernetes |

## Conceptos básicos

### Contenedor
Proceso empaquetado que se ejecuta aislado del resto de procesos:  
- Instancia ejecutable de una **imagen**.  
- Puede **crearse, iniciarse, detenerse, moverse o eliminarse** por línea de comandos, GUI o API.  
- Se ejecuta en **local o en la nube**.  
- Es **portable** y está aislado de otros contenedores y procesos.

### Imagen
Modelo para crear contenedores.  
- Utiliza un sistema de archivos aislado.  
- Pueden:
  - **Descargarse de un repositorio (DockerHub)**  
  - **Definirse a partir de un Dockerfile / Containerfile**

## Docker

### Instalación en Windows

1. Instalar **WSL**  
```bash
wsl --install -d distribución
# Ejemplo:
wsl --install -d ubuntu
```
2. Instalar **Docker Desktop**  
3. Añadir el usuario al grupo `docker-users`

> Para añadir el usuario al grupo:  
> Administración de equipos → Usuarios y grupos locales → Grupos → docker-users

---

### Instalación en Ubuntu

**1. Instalar paquetes necesarios y claves:**

```bash
sudo apt-get update
sudo apt-get install ca-certificates curl gnupg lsb-release
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
```

**2. Añadir el repositorio oficial:**

```bash
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/docker-archive-keyring.gpg] https://download.docker.com/linux/ubuntu $(lsb_release -cs) stable" | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
```

**3. Instalar Docker y añadir el usuario al grupo:**

```bash
sudo apt-get update
sudo apt-get install docker-ce docker-ce-cli containerd.io
sudo usermod -aG docker $USER
```

---

### Verificar la instalación

```bash
docker run hello-world
```

Si aparece:

> “Hello from Docker! This message shows that your installation appears to be working correctly…”

...significa que Docker está correctamente instalado.

## Docker: comandos básicos

### Comandos sobre imágenes

- Descargar una imagen:
  ```bash
  docker pull nombre_imagen
  ```
- Ver imágenes descargadas:
  ```bash
  docker image ls
  ```
- Eliminar una imagen:
  ```bash
  docker image rm nombre_imagen
  ```

---

### Comandos sobre contenedores

- Ejecutar un contenedor:
  ```bash
  docker run nombre_imagen
  ```
- En segundo plano:
  ```bash
  docker run -d nombre_imagen
  ```
- Especificando nombre:
  ```bash
  docker run --name nombre_contenedor nombre_imagen
  ```
- Redirección de puertos:
  ```bash
  docker run -p puerto_host:puerto_contenedor nombre_imagen
  ```

---

### Gestión de contenedores

- Mostrar contenedores en ejecución:
  ```bash
  docker ps [-a] [-q]
  # -a → todos los contenedores, -q → solo ID
  ```
- Arrancar o parar contenedores:
  ```bash
  docker start nombre_contenedor
  docker stop nombre_contenedor
  ```
- Eliminar contenedores:
  ```bash
  docker rm [-f] nombre_contenedor
  # -f → forzar
  ```

---

### Comandos sobre redes

- Mostrar redes:
  ```bash
  docker network ls
  ```
- Crear o eliminar:
  ```bash
  docker network create nombre_red
  docker network rm nombre_red
  ```
- Inspeccionar red:
  ```bash
  docker network inspect nombre_red
  ```

---

### Volúmenes

#### Tipos:
- **Volúmenes de Docker:** gestionados por Docker, almacenados en `/var/lib/docker/volumes/`.  
- **Bind mounts:** montan un directorio del sistema anfitrión en el contenedor.  
- **tmpfs:** montaje temporal en RAM (solo en Linux).

#### Comandos:
- Crear o eliminar:
  ```bash
  docker volume create nombre_volumen
  docker volume rm nombre_volumen
  ```
- Inspeccionar:
  ```bash
  docker volume inspect nombre_volumen
  ```
- Usar un volumen:
  ```bash
  docker run -v nombre_volumen:ruta_en_contenedor nombre_imagen
  ```
- Usar un bind mount:
  ```bash
  docker run -v ruta_anfitrion:ruta_en_contenedor nombre_imagen
  ```

## Dockerfile (Creación de imágenes)

Un **Dockerfile** (o *Containerfile*) es un archivo de texto que define cómo crear una imagen.

### Instrucciones habituales:
- `FROM`: imagen base  
- `RUN`: ejecutar comandos  
- `MAINTAINER`: autor  
- `ENV`: variables de entorno  
- `EXPOSE`: puertos  
- `ADD`: copiar archivos  
- `ENTRYPOINT`: comando principal

### Ejemplo:

```dockerfile
FROM debian
RUN apt-get update && apt-get install -y apache2 && apt-get clean && rm -rf /var/lib/apt/lists/*
ENV APACHE_RUN_USER www-data
ENV APACHE_RUN_GROUP www-data
ENV APACHE_LOG_DIR /var/log/apache2
EXPOSE 80
ADD ["index.html","/var/www/html/"]
ENTRYPOINT ["/usr/sbin/apache2ctl", "-D", "FOREGROUND"]
```

### Crear una imagen

```bash
docker build -t imagen:tag .
# El "." indica el directorio actual
```

## Docker Compose

Herramienta para desplegar varios contenedores de forma automatizada.

### Estructura del archivo `docker-compose.yml`

- **services:** definición de cada contenedor
- **volumes:** volúmenes compartidos
- **networks:** redes personalizadas

#### Parámetros comunes en cada servicio:
- `image`: imagen usada  
- `container_name`: nombre del contenedor  
- `hostname`: nombre del host  
- `environment`: variables de entorno  
- `ports`: redirección de puertos  
- `volumes`: volúmenes y bind mounts  
- `network`: red a la que se conecta  
- `command`: comando alternativo al de la imagen  

---

### Comandos Docker Compose

#### Lanzar contenedores
- **Arrancar todos los servicios definidos en el `docker-compose.yml` del directorio actual.**
  ```bash
  docker compose up                # arranca en primer plano, mostrando logs
  docker compose up -d             # arranca en segundo plano (detached)
  docker compose -f archivo.yml up # especifica un archivo concreto
  ```
- **Opciones prácticas al arrancar:**
  ```bash
  docker compose up --build        # recompila las imágenes si hubo cambios en el Dockerfile
  docker compose up --pull always  # fuerza la descarga de imágenes más recientes
  docker compose up --no-deps servicio # arranca un servicio sin levantar dependencias
  docker compose up --scale web=3  # escala el servicio 'web' a 3 réplicas
  ```

#### Parar y limpiar
- **Detener y borrar los contenedores creados por compose (mantiene volúmenes por defecto):**
  ```bash
  docker compose down
  docker compose -f archivo.yml down
  ```
- **Limpiezas más agresivas:**
  ```bash
  docker compose down -v           # elimina también volúmenes anónimos
  docker compose down --rmi local  # elimina imágenes creadas localmente
  docker compose down --remove-orphans # elimina contenedores huérfanos
  ```

#### Estado y gestión básica
- **Ver qué está en marcha y su estado:**
  ```bash
  docker compose ps
  ```
- **Arrancar/parar algunos servicios:**
  ```bash
  docker compose start servicio1 servicio2
  docker compose stop  servicio1 servicio2
  ```
- **Reiniciar servicios:**
  ```bash
  docker compose restart
  docker compose restart servicio
  ```

#### Ejecución dentro de contenedores
- **Entrar o ejecutar un comando en un servicio:**
  ```bash
  docker compose exec servicio bash
  docker compose exec servicio sh
  docker compose exec servicio env
  ```
- **Crear y ejecutar un contenedor efímero:**
  ```bash
  docker compose run --rm servicio comando
  ```

#### Logs y diagnóstico
- **Ver logs con filtros útiles:**
  ```bash
  docker compose logs
  docker compose logs servicio
  docker compose logs -f --tail=100
  docker compose logs --since=10m
  ```
- **Procesos en ejecución:**
  ```bash
  docker compose top
  ```

#### Compilación e imágenes
- **Construir imágenes definidas en `build:`:**
  ```bash
  docker compose build
  docker compose build servicio
  docker compose build --no-cache
  ```
- **Gestionar imágenes remotas:**
  ```bash
  docker compose pull
  docker compose push
  ```

#### Validación y configuración
- **Validar y visualizar la configuración efectiva:**
  ```bash
  docker compose config
  docker compose config --services
  docker compose config --profiles
  ```

#### Proyectos, perfiles y múltiples archivos
- **Nombre del proyecto (prefijo de contenedores y redes):**
  ```bash
  docker compose -p mi_proyecto up
  ```
- **Usar varios archivos:**
  ```bash
  docker compose -f compose.yml -f compose.prod.yml up -d
  ```
- **Activar perfiles:**
  ```bash
  COMPOSE_PROFILES=monitorizacion,debug docker compose up -d
  ```

#### Copias y archivos
- **Copiar archivos entre host y contenedor:**
  ```bash
  docker compose cp servicio:/ruta/en/contenedor archivo_local
  docker compose cp archivo_local servicio:/ruta/en/contenedor
  ```

---

#### Diferencias con `docker logs` clásico
Si necesitas los logs de un único contenedor por su nombre/ID, también puedes usar:
```bash
docker logs [-f] nombre_contenedor
```
Pero, para proyectos compose, suele ser más cómodo usar `docker compose logs`.

---
### Ejemplo
```yaml
version: "3.9"

services:
  web:
    image: nginx:latest
    container_name: servidor_web
    ports:
      - "8080:80"
    volumes:
      - ./html:/usr/share/nginx/html
    depends_on:
      - db
    networks:
      - appnet

  db:
    image: mysql:8.0
    container_name: base_datos
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: ejemplo_root
      MYSQL_DATABASE: ejemplo_db
      MYSQL_USER: usuario
      MYSQL_PASSWORD: contraseña
    volumes:
      - db_data:/var/lib/mysql
    networks:
      - appnet

volumes:
  db_data:

networks:
  appnet:
```
